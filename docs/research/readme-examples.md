# README examples for Gatto

Research date: October 14, 2026. Reviewed twelve first-party READMEs through GitHub's API and browsed representative GitHub pages. Recent activity below means the latest commit on the repository's default branch, checked with `gh api repos/{owner}/{repo}/commits?per_page=1`; it does not imply a recent release or promise continued maintenance. Dates are in America/Chicago.

## Findings

The useful shared pattern is a short statement of purpose, a visible download or getting-started route, then links to documentation organized around the reader's task. Kap is the closest compact app example; Rectangle contributes a practical URL-scheme example; the Vercel repositories demonstrate how little implementation detail a root README needs when other guides exist. These are editorial judgments based on the sources below.

## Established app examples

To inspect writing that already existed in 2021, rather than assume that an old repository's current README is old, reviewed five historical README revisions:

- [Rectangle, November 24, 2021](https://github.com/rxhanson/Rectangle/blob/28b090de8db26e8934c24dfe327e17e9ddec90ab/README.md): product identity, screenshot, system requirements, installation, then usage.
- [IINA, November 29, 2021](https://github.com/iina/iina/blob/09793cc78121675d884a54550197351044b10a0d/README.md): short macOS identity and website/releases links above features and building.
- [CotEditor, December 14, 2021](https://github.com/coteditor/CotEditor/blob/ebd326fc7ae7ecfd088679655c9c7cced494328d/README.md): one-sentence purpose, platform requirement, website/App Store links, screenshot, then source and build information.
- [Kap, November 26, 2021](https://github.com/wulkano/Kap/blob/8fd5d3aeb2fcc081538f1061e6dba5bcc6abe980/README.md): brief identity, macOS download, Homebrew command, and links to contributing/plugin guides. The short everyday-use paragraph is in the current README, not this historical revision.
- [Stats, November 28, 2021](https://github.com/exelban/stats/blob/61c96b69567418b73cceea9601853ffb80ea9f71/README.md): interface images and concrete purpose before installation, requirements, features, and support.

These revisions establish that the inspected layouts and wording existed in 2021. They do not establish who wrote every sentence or how later edits were produced.

## Application to Gatto

Recommendations below are the synthesis of this research, not claims made by the example projects.

1. Preserve the hero image and lead with one plain sentence naming macOS, GitHub pull requests, issues, comments, and the result the app produces. Keep setup directions in their own section, following [Rectangle's ordering](https://github.com/rxhanson/Rectangle/blob/main/README.md).
2. Keep a compact list of consequential user outcomes. Group related image-input and editing capabilities, rather than inventory every control; [React's three grouped features](https://github.com/react/react/blob/main/README.md) provide the structural example.
3. Give installation and everyday use different destinations. The README should make the download and first-use route obvious; setup owns prerequisites, authentication, configuration, and macOS approval steps; the walkthrough owns recurring interactions. [Kap](https://github.com/wulkano/Kap/blob/main/README.md) demonstrates concise routes to deeper guides.
4. Retain concrete URL examples in the README, with the full behavior and parameter reference owned by the relevant guide, drawing on [Rectangle's URL section](https://github.com/rxhanson/Rectangle/blob/main/README.md#execute-an-action-by-url).
5. Keep Rust, GPUI, and GPUI Kit as brief technology context, and link to the contributor guide for versions, development tools, build commands, and release work. [Turborepo](https://github.com/vercel/turborepo/blob/main/README.md) shows how a contributing link can carry that material.
6. Replace Gatto's vague size adjective with measured release-download and installed-app figures. Label the release, architecture, and units, and keep a reproducible measurement/update procedure in developer documentation. The reviewed READMEs are writing references, not evidence for Gatto's figures.
7. Explain the GitHub CLI → GitHub relationship once in the product overview, with configuration details linked from setup. Use a small documentation directory, modeled on [Workers SDK](https://github.com/cloudflare/workers-sdk/blob/main/README.md#documentation), to make the repository's guides discoverable without repeating their contents.
