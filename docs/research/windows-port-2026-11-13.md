# Windows desktop access and the Gatto port

Research date November 13, 2026. App baseline Gatto `v0.24.4`, commit
`7db2ee06fae36fdf582b7a29ff6badcf07648a4f`. Prices are US list prices. The port
assessment comes from the shipping source, release documentation, the exact
locked GPUI Windows source in the Cargo registry, and platform documentation.
The compatibility assessment below describes that baseline. See the prototype
follow-up for the build and VM evidence.

## Prototype follow-up

[Draft PR #48](https://github.com/jeremyc2/Gatto/pull/48) adds a native Windows x64
release build and a downloadable executable. See the PR for current test results
and the features deferred from the preview.

The no-card route used [UTM 5.0.8](https://github.com/utmapp/UTM/releases/tag/v5.0.8)
to emulate an x64 PC on this Apple Silicon Mac, with Microsoft's
[90-day Windows 11 Enterprise evaluation](https://www.microsoft.com/en-us/evalcenter/download-windows-11-enterprise).
The English x64 ISO matched [Microsoft's published checksum](https://support.microsoft.com/en-us/servicing/os/windows/docs/2026/09/verify-the-authenticity-of-a-windows-11-enterprise-evaluation-iso-file).
In UTM, eject the guest-tools ISO before booting Windows Setup. Its
[unattended answer file](https://github.com/utmapp/spice-nsis/blob/main/Autounattend.xml)
specifies a Windows Pro product key. With both discs connected, Enterprise Setup
rejected the key; with only the Microsoft ISO connected, it reached the license
agreement and began installing without a product key. Attach the guest-tools
disc after Windows is installed if needed.

The separately downloaded English Arm64 IoT Enterprise LTSC image did not match
the published hash and was not booted. VMware Fusion remains free, but the
[download requires Broadcom registration and screening](https://knowledge.broadcom.com/external/article/397417/downloading-free-software-from-the-broad.html).

## Recommendation

Keep Gatto in Rust and GPUI. Make **Windows 11 x64** the first release target
and use a Windows desktop to test the real app. Get one screenshot from Snipping
Tool through paste, annotation, project save, upload, and link copy before
porting the full set of desktop integrations. Treat ARM64 as a separate native
build target after the x64 path works.

## Windows desktop access from this Mac

This Mac uses Apple Silicon (`arm64`). The local options below run Windows in
a window on the Mac. The hosted options provide a desktop through a browser or
remote client.

### Recommended route

1. **Build the x64 executable and installer on GitHub Actions.** Add a `windows-2025` job using Rust's `x86_64-pc-windows-msvc` target once the app compiles for Windows. GitHub's standard hosted runners are free on public repos. The x64 runner image is Windows Server 2025 and has the Visual Studio build tools and Rustup. Run tests and publish a downloadable workflow artifact. Add `windows-11-arm` if Gatto commits to a native `aarch64-pc-windows-msvc` release. Gatto’s workflow definitions are currently disabled. A Windows job would be a new active workflow. Use one of the desktops below for manual testing. The trial plan doesn't advertise a dedicated GPU. ## What already has a Windows path

Gatto pins `gpui-kit` 0.9.1 and uses its default `gpui-pre` 0.3.12 backend. Its
locked Windows backend uses Direct3D 11 and DirectWrite. The backend already
implements Windows file dialogs, Explorer file drops, text and image clipboard,
file-path clipboard reads, and system notifications. It also has a Jump List
implementation. This is enough to justify trying the existing toolkit. Confirm
behavior in the exact build and install method before counting a feature as
working. [Gatto dependency notes](../../CONTRIBUTING.md#dependencies),
[GPUI Kit package](https://docs.rs/crate/gpui-kit/0.9.1),
[Zed Windows graphics guidance](https://zed.dev/docs/windows#graphics-issues).

Gatto itself has several hard build blockers. `desktop.rs`, `github/native.rs`,
and the annotation layout module use Apple APIs without a Windows implementation.
Other paths explicitly disable behavior outside macOS, including video preview,
compression, updates, and Rooftops score PNG export. The platform harness and
some tests use AppKit or Unix-only APIs. `build.rs` already skips the Objective-C
hotkey compilation on non-macOS targets. A build needs platform implementations
and a test split, plus a review of unguarded framework imports. [App entry
point](../../src/main.rs), [desktop adapter](../../src/desktop.rs),
[upload adapter](../../src/github/native.rs), [annotation layout](../../src/annotation/text/layout.rs),
[build script](../../build.rs), [platform harness](../../src/platform_tests.rs).

## First Windows test build

1. **Prove rendering first.** Build a minimal window with the exact GPUI Kit pin
   and test text rendering and focus on the chosen desktop. The locked backend
   enumerates DXGI adapters and requests D3D11 feature levels 11.1, 11.0, or 10.1
   with 4× MSAA and compute-shader support. It does not explicitly request WARP
   as a fallback, although Windows can expose a software adapter through DXGI.
   Run `dxdiag` in the guest and launch the window. On a Windows release build the
   GPUI build script compiles HLSL with `fxc.exe` from the Windows SDK. Use the
   native Windows MSVC toolchain in CI and try a release build early.
   [GPUI backend snapshot](https://crates.io/crates/gpui-pre-windows),
   [Microsoft WARP documentation](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/directx-warp),
   [Zed Windows development instructions](https://zed.dev/docs/development/windows),
   [Microsoft Rust setup](https://learn.microsoft.com/en-us/windows/dev-environment/rust/setup),
   [Rust MSVC targets](https://doc.rust-lang.org/stable/rustc/platform-support/windows-msvc.html).
2. **Test the main workflow end to end.** Import an in-guest Snipping Tool image,
   add an arrow and text, save and reopen the project, then upload to a test repo
   and paste the result in a browser. Add Explorer multi-file paste/drop, a GIF,
   a video under the upload cap, and a batch with a failed or canceled request.
   Check both generated snippets and the saved bytes after restart.
3. **Test Windows behavior on an installed build.** Check file associations and
   protocol launches with an existing window and after quitting. Test the tray,
